# Окремий PAPER-пілот IKIGAI для Юрія

Цей пакет запускає **PAPER на реальних публічних котируваннях OKX**. Угоди,
комісії й funding моделюються. Баланс біржі не використовується; платного Jev немає.
Ключі не потрібні й до цієї папки їх копіювати не треба.

## Запуск

1. Скопіюй ZIP на другий комп’ютер і **розпакуй повністю**, наприклад у
   `C:\JevArena-PAPER`. Не запускай файли прямо з вікна архіватора.
2. Потрібен Python 3.12 з Python Launcher. Перевір у командному рядку:
   `py -3.12 --version`. Якщо його немає, встанови Python 3.12 через
   [офіційний Windows installer](https://www.python.org/downloads/windows/)
   з компонентом Python Launcher. Інших Python-пакетів установлювати не потрібно.
3. Натисни `CHECK_PACKAGE.cmd`. Має з’явитися `PORTABLE_PAPER_PACKAGE_OK`.
   Перевірка не починає бій і не робить API-запитів.
4. Перед стартом у параметрах Windows → Система → Живлення вимкни сон на час
   роботи від мережі. Підключи живлення та стабільний інтернет. Увімкни автоматичний
   час і синхронізацію в Дата й час. Закриття кришки ноутбука не повинно присипляти його.
5. Запусти **один** файл: `START_PAPER_5H.cmd`.
   Це вибір вікна для нових входів. Залиш вікно командного рядка відкритим.
6. Відкрий у браузері **цього другого комп’ютера**
   [арену](http://127.0.0.1:8766/arena?mode=paper). Браузер можна закрити;
   вікно процесу та сам комп’ютер залишаються ввімкненими.

Склад і правила зафіксовані в `NEXT_RUN_PLAN.json`. Чотири V1 залишаються
контрольними стратегіями. Юрій бере участь із геометричною адаптацією IKIGAI G1,
формалізованою AI: H1/H4, пробій B, стоп за E, ціль за висотою фігури.
Це перша перевірка її механіки на майбутніх ринкових даних, не доказ прибутковості.
Історія на старті служить для підготовки: минулі сигнали не виконуються заднім числом.
За ніч підтверджений трикутник може не виникнути — тоді буде чесний результат без входу.

Після дедлайну нові входи та докупівлі заборонені. Відкрита позиція продовжує
власні правила виходу. G1 має свій максимальний строк утримання 24 години,
тому весь прогін може тривати довше обраного вікна. Дочекайся **«Завершено»**
та відсутності відкритих позицій. DRAINING означає, що позиції ще завершуються.

Повторний запуск тієї самої папки відкриває попередній раунд, нового не створює.
Маркер `runtime/portable-paper-once.json` зберігає цю межу навіть після збою;
його не потрібно видаляти. Для PAUSED і фінального DONE створюються окремі
спроби експорту, щоб проміжний ZIP не замінив фінальний.
`OPEN_RESULTS.cmd` відкриває перегляд без старту. Одночасно потрібен лише один
процес цього пакета. Якщо порт зайнятий, закрий друге зайве вікно, не видаляй журнали.
Папка попереднього бою на першому ПК залишається його архівом; новий пакет має
окремий PAPER-стан і не переносить або скидає біржові ліміти Jev.

## Як передати результати для повного аналізу

Після завершення пакет сам збере файл **`exports\Battle-…-PAPER-….zip`**.
Разом з ним з’являться квитанція перевірки й, якщо звіт уміщається в межу
візуалізації, читабельний HTML. Саме **Battle ZIP** надішли в цей чат.

У ньому будуть усі записані події, склад і точні версії, правила запуску,
котирування та доступний старший контекст, сигнали й причини очікування,
модельні fills, витрати/funding, результати, пропуски та причинний повтор.
Цілісність кожного файла перевіряється SHA-256. Нульові входи й неповні
результати зберігаються, а не зникають зі звіту.

Якщо автоматичний ZIP не створився: після завершення запусти `EXPORT_BATTLE.cmd`.
Або в арені вибери раунд → **«Зберегти бій · ZIP»**. Не надсилай файл початкової
програми замість Battle ZIP. Для звичайного аналізу API-файли не потрібні.

Якщо комп’ютер заснув, вимкнувся або процес упав, збережи всю папку.
`EXPORT_BATTLE.cmd` збере доступний запис із позначкою неповного прогону;
програма не оголошує невідому позицію закритою і не починає новий бій автоматично.
Для додаткової діагностики надішли Battle ZIP та текст помилки.
Якщо експортер теж відмовив — заархівуй **лише `runtime` цього PAPER-пакета**,
`paper-package.json` і `NEXT_RUN_PLAN.json`. У цьому спеціальному пакеті немає ключів.
Ця порада не поширюється на приватний runtime основної Live-інсталяції.

## Окремо про реальні кошти

Новий ключ Юрія перевіряється окремим read-only інструментом у головному проєкті.
Цей ZIP не є Live-запуском і не підключає G1 до реальних коштів. Допуск G1 до
біржового виконання потребує окремої перевірки абсолютного стопа, розміру,
ACK/часткових fills і відновлення. Перевірений ключ сам по собі не підтверджує ці механізми.
