# Арена на Windows Server

Збірка переносить цю саму арену на Windows Server. Нові OKX акаунти не потрібні:
залишаються ті самі чотири субакаунти, рецепти, історія та сукупні ліміти Jev.
Запуск серверної панелі не починає бій. Кожний бій запускає власник кнопкою в панелі.

## Три різні файли

| Файл | Для чого |
|---|---|
| JevArena-WindowsServer.zip | Програма, інтерфейс, встановлення. Без ключів і торгової історії. |
| JevArena-state.private.zip | Особисте перенесення: журнали, рецепти, ліміти та наявні файли ключів. Лише на твій сервер; у чат не надсилати. |
| JevArena-battle-exchange-ID.zip | Один бій для аналізу. API-ключів та підписів запитів немає; саме цей файл надсилай координатору. |

## 1. Підготуй сервер

1. Підключись до Windows Server через віддалений робочий стіл.
2. Встанови Python 3.12 через повний Windows installer, Customize installation →
   Install for all users; Python launcher також для всіх користувачів.
   Перевір командою: py -3.12 --version.
3. Розпакуй JevArena-WindowsServer.zip у C:\. Отримаєш C:\JevArena.

Панель слухає лише 127.0.0.1:8765. Її відкриваєш у браузері на віддаленому робочому
столі сервера. Публічний порт чи додатковий пароль панелі не налаштовуються.
Python runtime не включений у ZIP; сторонні Python пакети не потрібні.

## 2. Перенеси стан із комп’ютера

Поточний бій спочатку завершується, усі його позиції мають бути нульовими.
Збірка не переносить активного торгового worker і не продовжує його автоматично.
Після аварії поточний executor має тільки owner close-only recovery; завершення
відкритої позиції на іншому ПК не видаємо за звичайне продовження стратегії.

1. На комп’ютері запусти C:\Projects\Trading\EXPORT_SERVER_STATE.cmd.
   Він перевірить відсутність незавершених циклів, закриє лише впізнаний idle HTTP
   server цього проєкту та збере стан. За активного бою відмовиться.
2. З’явиться C:\Projects\Trading\JevArena-state.private.zip.
   У ньому також наявні профільні .env.okx.*.local і .env.local.
   Вони не друкуються, не потрапляють у Git чи файл аналізу.
3. Перенеси цей приватний ZIP на сервер. Перетягни його на
   C:\JevArena\IMPORT_SERVER_STATE.cmd.
4. Перенесення дозволено лише в папку без попереднього runtime. Історію або ledger
   іншої інсталяції не перезаписуємо. Після експорту локальна панель заблокована
   маркером server_handoff.json, щоб випадково не працювати на двох машинах.

Старі журнали й SQLite, включно з WAL-файлами, переносяться без скидання лімітів.
Файли перевіряються за SHA-256. Файл налаштувань зберігає ті самі назви й прив’язки
субакаунтів. ОС-блокування захищають процеси на одній машині; вони не є глобальним
блокуванням між двома серверами. Приватний архів імпортуй тільки на один сервер.
Якщо експорт перервано і залишились маркер та .zip.pending, збережи обидва:
повний pending ZIP може містити підготовлений стан. Не видаляй маркер для запуску
старої копії; спочатку перевіримо й завершимо саме перенесення.
Межа одного перенесення — 2 GiB початкових файлів і 100 000 файлів. Перевищення
відхиляється; історія й ліміти не очищаються для обходу цієї межі.

Експорт залишає старі локальні preview-скрипти на комп’ютері й переносить тільки
стан та історію; програмний код уже є в збірці. При відмові показується конкретний
код причини. `pending_transfer_requires_review` означає зберегти `.pending` для
перевірки; `workspace_already_handed_off` — зберегти готовий архів і маркер,
а не повторювати перенесення або прибирати захист локальної копії.

## 3. Увімкни фонову панель

1. На сервері запусти C:\JevArena\INSTALL_WINDOWS_SERVER.cmd від адміністратора.
2. Скрипт перевірить програму та повний імпорт стану. Створить завдання
   Jev Trading Arena від SYSTEM: запуск при завантаженні ОС, одна інстанція,
   без обмеження тривалості. Пароль адміністратора в скриптах не зберігається.
3. Відкрий на сервері http://127.0.0.1:8765/arena.
4. У Керуванні перевір Read-only доступ до субакаунтів; якщо OKX ключ має IP
   allowlist, додай IP цього сервера в налаштуваннях того самого ключа.
5. Вибери склад, окремі наявні субакаунти, бюджет і режим. Для перевірки правил
   без вето Jev явно вибери RULES_ONLY · Jev SHADOW; типовий режим досі Jev-гейт.
6. Запусти бій сам у панелі. Від’єднай RDP через Disconnect; сервер і бій продовжать
   працювати. Комп’ютер можна вимкнути. Сам Windows Server має залишатися увімкненим.

Завдання перезапускає тільки панель після збою, максимум 3 спроби. Після перезапуску
воно не відновлює торгівлю: незавершений бій показує PAUSED, відновлення звірки та
закриття запускає власник. Час admission, авторські виходи, hosted SL, ризик і бюджети
не змінені. Завершення вікна входів не закриває відкриті позиції через сам таймер.

Перевірка завдання в PowerShell на сервері:

    Get-ScheduledTask -TaskName 'Jev Trading Arena'
    Get-ScheduledTaskInfo -TaskName 'Jev Trading Arena'

Короткий лог панелі: C:\JevArena\runtime\server\panel.log, ротація 3 × 4 MiB.
Повні торгові журнали окремо в runtime\exchange_v1, збереження не обрізається цим логом.
Оновлювати/зупиняти серверний процес можна лише після завершення боїв і позицій.
Повернення на комп’ютер робиться новим повним холодним перенесенням стану; не видаляй
маркер і не запускай стару копію з попередніми лімітами.

## 4. Збережи бій і надішли для аналізу

На арені обери потрібний раунд → Зберегти бій · ZIP.
Та сама кнопка є на сторінці Розбір і повтор.
За активного бою написано Зберегти поточний запис · ZIP: це проміжний знімок,
не фінальний результат. Завершений файл показує справжню якість звірки; статус DONE
сам по собі не замінює incomplete/settlement.

ZIP містить:

- battle-review.json: весь записаний порядок подій, перевірки ознак, funnel,
  цикл і actual fills, net PnL, signed fees/funding, окремий Jev USD, факти якості.
- battle-replay.json: причинний повтор із доступністю інформації на кожному кроці.
- strategies.json: зафіксовані повні рецепти й версії всіх учасників.
- match-settings.json: бюджет, час, правила визначення переможця, ліміти бою.
- market.jsonl: перевірені записані публічні котирування, свічки та ознаки.
- manifest.json: статус, повнота, межа подій, SHA-256 кожного файлу.
- README_UA.txt: коротке пояснення.

Секрети, Authorization, account UID, приватні API-відповіді та вільний текст причин
Jev виключені. Це приватний пакет аналізу, не автоматичний публічний показ.
Відсутні в старих журналах дані не домальовуються; пропущені ринкові рядки рахуються.
Ринкові ознаки перераховані з записаних публічних даних чинним кодом експорту;
фактичні значення перевірок під час бою залишаються в battle-review.json.
Надішли весь ZIP у чат, додавши «проаналізуй бій, рішення кожної стратегії й Jev».
Файл перенесення з private у назві для цього не використовуй.
Один пакет бою обмежено 512 MiB розпакованих даних; перевищення дає помилку,
а не прихований обрізаний журнал. Одночасно готується лише один пакет.

Перевірити отриманий файл локально без API й моделей:

    py -3.12 tools/analyze_battle_file.py JevArena-battle-exchange-ID.zip

## Підтвердження та джерела

Збірка і перевірки виконуються локально на підставних даних. Реальний Windows Server,
24-годинний запуск і OKX доступ із його IP перевіряє власник після встановлення.
Асистент не встановлює task на твій комп’ютер/сервер, не переносить активний бій,
не запускає реальні ордери та не викликає платний Jev.

Офіційні джерела для підготовлених команд:
[Python для Windows](https://docs.python.org/3.12/using/windows.html),
[Microsoft: параметри Scheduled Task](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset?view=windowsserver2025-ps),
[Microsoft: SYSTEM principal](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtaskprincipal?view=windowsserver2025-ps).
