# Калібрування треку K-T (ворота К для довгого горизонту) · 2026-11-17

Скрипти й виводи, з яких узято числа `team/judge/GATE_K_LONG_UA.md`, розд. 6. Це робочі скрипти Судді в тому вигляді, як вони запускались; виводи — як надруковані, без локальних шляхів.

**Що тут не запускається.** Жодне справжнє торгове правило на справжньому шляху DEV. Стратегії синтетичні (випадковий потік угод, оракул із шумом), а трендові правила в `kt_pathdep*.py` працюють лише на штучних цінах. Дані — лише DEV, денні закриття.

| Файл | Що робить | Вивід |
|---|---|---|
| `dev_daily.py` | денні закриття й фандинг BTC, ETH, SOL зі сховища DEV у `dev_daily.json` (у репозиторій не кладеться) | — |
| `kt_calibrate2.py` | спільні функції: генератор синтетичних угод, перевірки, тест зсувом. Його власний `main` — рання версія калібрування, числа з неї не взято | — |
| `kt_calibrate4.py` | одиночна форма T4: автор подає найкращу з m = 1, 4, 8, 12, 24; сирі значення в `kt_raw4.npz` | `kt_calibrate4.out` |
| `kt_calibrate5.py` | сімейна форма проти одиночної, незалежні й схожі родини; `kt_raw5.npz` | `kt_calibrate5.out` |
| `kt_analyze.py` | таблиці із сирих файлів за варіантами порогів | `kt_analyze.out` |

| `kt_decay.py`, `kt_decay2.py` | стратегія з перевагою лише до кінця 2023 року: що додають T5 і T6, варіанти порогів | `kt_decay.out`, `kt_decay2.out` |
| `kt_bootstrap_null.py` | скільки стратегій без вибору моменту проходить блоковий бутстреп днів у ринку (пропозиція Sol), поруч із K-T | `kt_bootstrap_null.out` |
| `kt_tool_check.py`, `kt_tool_check_family.py` | звірка `tools/gate_k_long.py` з функціями калібрування на синтетичних списках угод | друкують різницю p |

**Як відтворити.** `S` — порожня робоча тека, `R` — корінь репозиторію; скрипти скопіювати в `S`.

```
py -3.12 -X utf8 -B dev_daily.py R S/dev_daily.json
py -3.12 -X utf8 -B kt_calibrate4.py S 1000 400 S/kt_raw4.npz
py -3.12 -X utf8 -B kt_calibrate5.py S 600 300 S/kt_raw5.npz
py -3.12 -X utf8 -B kt_analyze.py S
py -3.12 -X utf8 -B kt_skill_scale.py S 150
py -3.12 -X utf8 -B kt_pathdep.py S 400
py -3.12 -X utf8 -B kt_pathdep2.py S 400
py -3.12 -X utf8 -B kt_decay.py S 300
py -3.12 -X utf8 -B kt_decay2.py S 300
py -3.12 -X utf8 -B kt_bootstrap_null.py S 300
py -3.12 -X utf8 -B kt_tool_check.py S R
py -3.12 -X utf8 -B kt_tool_check_family.py S R
```

Зерна записані в скриптах, тож числа відтворюються точно. Разом ≈ 40 хв на одному ядрі, пам'яті < 100 МБ на процес.

**Примітки.**
- У `kt_calibrate2.py` тест зсувом за замовчуванням відкидає зсуви менше 7 днів. Пізніші скрипти перемикають його на всі зсуви (`kc.shift_p.__defaults__ = (1,)`), як в інструменті: з відкиданням найближчих зсувів малі пороги (0,002) давали завищену частку хибних проходів.
- `kt_analyze.out` рахує правило з остаточними порогами таймінгу (E2 0,10, хвіст 0,50) і варіанти для порівняння. Рядки «pass with …» у `kt_calibrate4.out` і `kt_calibrate5.out` надруковано під час прогону ще з E2 = 0,25; таблиці документа взято з `kt_analyze.out`.
- У `kt_calibrate2.py` «без найкращого півріччя» рахує п'ять півріч, інструмент — шість (з неповним другим півріччям 2026). Інструмент трохи суворіший.
